# Правила коммитов

В этом репозитории коммиты делаются **только на русском языке** в **повелительном наклонении**.

## Формат сообщения

```text
[<TASK-ID>] <type>(<scope>): <что сделать>

<Контекст задачи и почему это нужно сделать>

Добавить:
- <файл/модуль>: описание нового

Изменить:
- <файл/модуль>: описание изменений
- <класс.метод>: описание изменений

Переместить:
- <откуда> → <куда>: зачем

Удалить:
- <файл/модуль>: что и почему убрано

<Результат работы>
```

`<TASK-ID>` — обязательный ключ задачи из Jira, например `[PROJ-123]`.
Указывается в начале первой строки. Нужен для автоматической связки коммита с
задачей в трекере.

Блоки операций включаются только при необходимости и всегда в таком порядке:

| Блок | Когда использовать |
| --- | --- |
| `Добавить` | новый файл, класс, метод, документ |
| `Изменить` | правка существующего файла/класса/метода |
| `Переместить` | переименование или перенос без изменения сути |
| `Удалить` | что-то убрано из репозитория — обязательно с причиной |

## Типы коммитов (`<type>`)

| type       | Назначение |
|------------|------------|
| `feat`     | Новая функциональность |
| `bugfix`   | Исправление ошибки в текущей разработке или тестовой среде |
| `hotfix`   | Срочное исправление критической ошибки в продакшене |
| `refactor` | Перестройка кода без изменения поведения |
| `docs`     | Документация: README, XML-комментарии, OpenAPI |
| `chore`    | Конфиги, скрипты, зависимости, `.editorconfig` |
| `test`     | Юнит-, интеграционные, сквозные и нагрузочные тесты |
| `style`    | Форматирование без изменения логики |
| `perf`     | Улучшение производительности |
| `build`    | Сборка, пакеты, `.csproj`, `Directory.Build.props` |
| `release`  | Подготовка релиза, версии, changelog, теги |
| `cleanup`  | Удаление мёртвого кода и неиспользуемых файлов |

## Область (`<scope>`)

| scope | Применение |
| --- | --- |
| `api` | `src/Reon.Api` — HTTP, auth, controllers, DTO, health |
| `core` | `src/Reon.Core` — домен, интерфейсы, сценарии |
| `infra` | `src/Reon.Infrastructure` — EF Core, S3, background workers |
| `db` | Миграции и схема Postgres |
| `docker` | `Dockerfile`, `docker-compose.yml` |
| `tests` | `tests/**` |
| `docs` | `README.md`, `CONTRIBUTIONS.md` |
| `config` | `appsettings*.json`, `global.json`, `.editorconfig` |

Если изменения затрагивают несколько областей — лучше разбить на несколько
коммитов. Если без области совсем не обойтись, её можно опустить.

## Пример правильного коммита

```text
[REON-123] feat(api): добавить получение метаданных файла

Модулям нужен JSON-эндпоинт, чтобы не читать S3-заголовки самостоятельно.

Добавить:
- src/Reon.Api/Controllers/FilesController.cs: метод GetMetadata
- src/Reon.Api/Contracts/FileMetadataResponse.cs: DTO метаданных

Изменить:
- src/Reon.Core/Services/FileStorageService.cs: добавить GetMetadataAsync

Проверено через Scalar UI и unit-тесты.
```

## Правила

- Заголовок — в повелительном наклонении: «добавить», «исправить», «настроить».
- Писать на русском языке.
- Описывать конкретно, что сделано, без «правки», «фиксы», «всякое».
- Внутри блоков перечислять файлы/классы/методы с кратким описанием.
- В «Результат работы» — проверяемый итог.
- Один коммит — одно логическое изменение.
- Не коммитить секреты, реальные пароли и ключи. Dev-значения из
  `appsettings.Development.json` допустимы только для локального стенда.

## Окончания строк

`.editorconfig` задаёт CRLF в рабочей копии, а `.gitattributes` — `text=auto
eol=crlf` для текстовых файлов. Git хранит текст с LF; LF в рабочей копии
остаётся только у `Dockerfile`, `.dockerignore` и shell-скриптов. Менять эти
настройки нужно только вместе.

- Не смешивать CRLF и LF внутри одного файла: именно на такой смеси Visual
  Studio показывает диалог «Несовместимые завершения строк».
- Правки скриптами и генераторами делать с сохранением окончаний файла, а
  после массовых изменений проверять рабочую копию:

```bash
git ls-files --eol | grep 'w/mixed'
```

Пустой вывод — всё в порядке. Если файл попал в список, привести его целиком
к CRLF и убедиться, что `git diff` пуст: в Git те же файлы хранятся с LF.
